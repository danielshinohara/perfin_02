  1. Add New → Project → importe danielshinohara/perfin_02 → Root Directory = Aplicativo → Framework Next.js → Deploy. Anote a URL gerada (abaixo chamada de <URL-DO-PORTAL>, por exemplo https://perfin-02-portal.vercel.app).
  2. No projeto do Portal, em Settings → Environment Variables (Production e Preview), cadastre:
    VariávelValor
    NEXT_PUBLIC_SITE_URL<URL-DO-PORTAL> (sem barra no fim)
    NEXT_PUBLIC_SUPABASE_URLhttps://hesrhxonnnoyjjodebzm.supabase.co
    NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEYSupabase → Project Settings → API Keys → Publishable key
    GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRETGoogle Cloud → Clientes → cliente Web
    ADMIN_USUARIOo e-mail do administrador
    GEMINI_API_KEYGoogle AI Studio
    TOKEN_ENCRYPTION_KEYgerar com node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
  3. No projeto perfin-02-site, cadastre PORTAL_URL = <URL-DO-PORTAL> e NEXT_PUBLIC_SITE_URL = URL do site.
  4. Faça Redeploy dos dois projetos.
  5. Opcional: reautorize o conector da Vercel no Claude para o escopo daniel-shinohara. Assim eu consigo conferir deploys e nomes de variáveis (nunca os valores).

Deu certo se: <URL-DO-PORTAL>/login abre a tela com as abas Entrar | Criar conta, e o site mostra o Termômetro com os botões no cabeçalho.

SUPABASE_SECRET_KEY e DATABASE_URL não vão para a Vercel.

  2. Google Auth Platform → Branding → Domínios autorizados: inclua supabase.co e vercel.app (ou o domínio próprio, se houver).

  4. Google Auth Platform → Clientes → seu cliente Web:
    • Origens JavaScript autorizadas: <URL-DO-PORTAL>
    • URIs de redirecionamento autorizados: https://hesrhxonnnoyjjodebzm.supabase.co/auth/v1/callback
    Salve. A alteração pode levar alguns minutos para valer.
  5. Gere um novo client secret (o atual ficou exposto no DadosPerfin.txt), desative o antigo e atualize a Vercel (A) e o Supabase (C).
Publicação do app no Google: enquanto o app OAuth estiver em modo Testing, só os e-mails cadastrados em Público-alvo → Usuários de teste conseguem "Continuar com Google", e o acesso ao Drive, Agenda e Gmail expira a cada 7 dias. Para abrir o login Google a qualquer pessoa é preciso publicar o app. Com o escopo do Gmail (restrito), o Google exige uma verificação que pode levar semanas. O cadastro por e-mail e senha funciona sem isso. Se quiser, numa próxima etapa o portal pode pedir esses escopos só quando a pessoa usar Relatórios ou Agenda, o que dispensa a verificação para quem só quer entrar.

Deu certo se: "Continuar com Google" abre a tela de consentimento do Google com o nome do app, e não aparece o erro redirect_uri_mismatch.

C Supabase — projeto perfin_02

As tabelas (migrações 0001 e 0002) eu aplico pelo conector antes do merge. Os passos abaixo ficam no painel de Authentication.

  1. Sign In / Providers → Email: ativo; Confirm email ligado; Minimum password length = 10; se disponível no seu plano, ligue Prevent use of leaked passwords.
  2. Sign In / Providers → Google: ativo, com o Client ID e o (novo) Client Secret. Confira que a Callback URL mostrada ali é https://hesrhxonnnoyjjodebzm.supabase.co/auth/v1/callback.
  3. URL Configuration:
    • Site URL: <URL-DO-PORTAL>
    • Redirect URLs (adicione as duas): 
      <URL-DO-PORTAL>/auth/callback
<URL-DO-PORTAL>/auth/confirmar**
  4. Emails → Templates → Confirm signup: troque o link do corpo por: 
    <h2>Confirme seu cadastro no Portal Perfin</h2>
<p><a href="{{ .SiteURL }}/auth/confirmar?token_hash={{ .TokenHash }}&type=email">Confirmar meu e-mail</a></p>
<p>Depois de confirmar, um administrador vai liberar seu acesso.</p>
  5. Emails → Templates → Reset Password: 
    <h2>Nova senha do Portal Perfin</h2>
<p><a href="{{ .SiteURL }}/auth/confirmar?token_hash={{ .TokenHash }}&type=recovery">Criar uma nova senha</a></p>
<p>Se você não pediu, ignore este e-mail.</p>
  6. Emails → SMTP Settings: configure um SMTP próprio (por exemplo Resend, Brevo, SendGrid ou o SMTP do Google Workspace), com remetente do domínio da Perfin.
    Sem SMTP próprio, o Supabase só envia e-mails para membros da equipe do projeto e com limite baixo por hora. Ou seja, pessoas de fora não recebem a confirmação de cadastro.
  7. Hooks: o Before User Created deve ficar desligado (a função antiga foi removida). Se ele estiver ligado, nenhum cadastro novo funciona.
  8. Sign In / Providers → Email: se a opção existir no seu painel, ligue Secure password change.
  9. Multi-Factor: ative o TOTP (recomendado para o admin).

Deu certo se: ao criar uma conta de teste chega o e-mail "Confirme seu cadastro". O link abre a página "Confirmar seu e-mail" e, depois do clique no botão, a tela "Cadastro recebido". O botão existe porque antivírus de e-mail abrem os links sozinhos e gastariam o link antes de você.

D Administrador

  1. SQL Editor (depois que eu avisar que as migrações foram aplicadas), troque o e-mail e rode: 
    insert into public.administradores (email) values ('seu-email-de-admin@exemplo.com');
    Use o mesmo e-mail de ADMIN_USUARIO, em minúsculas.
  2. Em Authentication → Users, procure esse e-mail. Se já existir um usuário com ele que não foi você quem criou (alguém pode ter se cadastrado antes), apague-o. Não o confirme.
  3. Authentication → Users → Add user → Create new user: o mesmo e-mail, com uma senha forte e nova, e Auto Confirm User marcado. Como o e-mail está em administradores e já vem confirmado, o admin nasce ativo.
  4. Entre no portal pela aba Entrar com esse e-mail e senha e cadastre o TOTP, se tiver ativado.

Deu certo se: o menu lateral mostra o grupo Administração com Usuários e Alertas.
